# ТЗ для Codex, этап 0: каркас тренажёра «Инспектор труда» и стиль
Проект: `C:\Projects\mrot-trainer` (папка уже создана, в `docs\` лежат ТЗ и референсы). Автор задачи: Кай (ПМ), 17.11.2026.

## Цель этапа
Собрать рабочий каркас одностраничного веб-тренажёра и дизайн-систему в стиле «тёмный архив», плюс один играбельный экран уровня 3 «Карточки работников» на ДЕМО-данных. По этому этапу Артём оценит внешний вид, поэтому стиль здесь важнее объёма.

  - Макеты `MROT_v2_*.jpg` Артёму НЕ понравились, на них не ориентируйся.

## Стек (обязательно)
- Vite + TypeScript (strict) + Preact. Без бэкенда, без внешних API, без аналитики и трекеров.
- Тесты: Vitest.
- Анимации: CSS (transitions/keyframes). GSAP можно, если нужно. Учитывать `prefers-reduced-motion`.
- Шрифты подключать локально, файлами в репозитории (не Google CDN), только OFL с кириллицей: Source Serif 4 или PT Serif (заголовки), Golos Text или IBM Plex Sans (интерфейс), IBM Plex Mono (номера, формула, суммы). Лицензии положить рядом.
- Офлайн: PWA (vite-plugin-pwa или свой service worker). После первого открытия игра должна работать без интернета.
- Деплой: GitHub Actions workflow для GitHub Pages (`.github/workflows/deploy.yml`) с правильным `base`. Ничего не пушить и репозиторий на GitHub не создавать: это сделаем отдельно после проверки.

## Что сделать
1. Каркас: экраны «Титул», «Выбор уровня» (4 уровня + финал, пока открыт только уровень 3), «Уровень 3», «Об игре / источники». Переходы между экранами с аккуратной анимацией (например, открытие папки, сдвиг документа).
2. Дизайн-система в `src/ui/`: токены (цвета, отступы, тени, шрифты) в CSS-переменных; компоненты «Папка дела», «Документ/бланк», «Штамп» (с анимацией прижатия), «Кнопка», «Поле ввода суммы» (₽, пробелы между разрядами), «Подсказка», «Панель XP/звания», «Переключатели звука и музыки». Бумага с лёгкой фактурой без нечитаемой грязи; цифры всегда хорошо читаются.
3. Расчётное ядро `src/calc/`, чистые функции без UI:
   - `applicableMinimum(B, k, s)`, считается как B × (k + s);
   - выбор базы: МРОТ или региональный минимум, если он задан и выше;
   - `underpayment(salary, minimum)`, это max(0, minimum − salary);
   - округление вынести в одну функцию с режимом из конфига. Сейчас временно до копеек, half-up, и в коде пометка `TODO(Эрика): правило округления по методичке v5`;
   - считать в копейках (целые числа), без ошибок плавающей точки;
   - генератор задач с seed (детерминированный PRNG, например mulberry32): одинаковый seed даёт одинаковую задачу.
   - Тесты: формула, выбор базы, недоплата ≥ 0, отсутствие плавающих ошибок, воспроизводимость по seed. Эталонные примеры из методички добавим позже, оставь для них пустой файл-фикстуру.
4. Уровень 3, демо: карточка вымышленного работника (учебный регион вроде «Северный край», вымышленные ФИО и компания). Игрок решает «нарушение есть / нет», при нарушении вводит недоплату.
   - Первая ошибка даёт короткую подсказку, повторная — пошаговый разбор и строку «Повторить: часть N, п. X методички» (пока заглушка).
   - Ответ сам не раскрывается.
   - XP по правилам из ТЗ (+100, +70, +50, серия +50).
   - После верного ответа ставится штамп «Проверка завершена».
   - 5 карточек за прохождение.
   - Все числа на этом этапе демо, на экране «Об игре» явно написать, что данные демонстрационные.
5. Прогресс в localStorage (XP, звание, пройденное) и кнопка «Начать заново».
6. Звук: Howler.js или Web Audio. Музыка по умолчанию выключена, эффекты тихие, оба переключателя запоминаются. Если свободных звуков с понятной лицензией (CC0) под рукой нет, сделать тихие синтезированные эффекты через Web Audio (щелчок, штамп, перелистывание), без скачивания сомнительных файлов.
7. Изображения: без чужих картинок. Фоны, фактуры и иконки делать через CSS/SVG. Портреты работников заменить стилизованным силуэтом или монограммой. Позже их можно будет заменить сгенерированными.
8. Адаптивность: телефон вертикально (от 360 px) и проектор 16:9 (1920×1080), крупные зоны нажатия, хороший контраст.
9. Файлы: `README.md` (запуск, сборка, деплой), `CREDITS.md` (шрифты и всё стороннее с лицензиями), `CHANGELOG.md`.

## Ограничения
- Весь интерфейс на русском, без латинских заглушек.
- Не выдумывать реальные цифры МРОТ, региональные минимумы и пункты методички. Где нужны реальные данные, оставь `TODO(Эрика)`.
- Реальные регионы не смешивать с выдуманными коэффициентами. На этом этапе используются только вымышленные регионы.
- Без шляп, жалюзи, крови, пробковой доски, неона и советской символики.
- Не трогать ничего за пределами `C:\Projects\mrot-trainer`. Не пушить, не публиковать, не ставить глобальные пакеты.
- `git init` и локальные коммиты можно, по одному осмысленному коммиту на пункт.

## Критерии приёмки
- `npm ci && npm run build && npm test` проходят без ошибок. `npm run dev` открывает игру.
- `npm run preview`: уровень 3 проходится целиком (5 карточек), XP начисляется по правилам, прогресс переживает перезагрузку страницы.
- После первой загрузки и отключения сети страница открывается и играется (PWA).
- На 360×740 и 1920×1080 ничего не обрезается и не налезает.
- Тесты ядра покрывают формулу, выбор базы, недоплату, копейки и seed.
- Lighthouse (mobile): Performance ≥ 85, Accessibility ≥ 90. Если не получается, напиши почему.
