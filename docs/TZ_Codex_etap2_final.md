# ТЗ для Codex, этап 2: финал «Дело № 001» и «Акт проверки»
Проект: `C:\Projects\mrot-trainer`. Автор: Кай, 18.11.2026. Этап 1 (уровень 4) принят. Источник: docs\TZ_Inspektor_truda_v1.md — «Финал „Дело № 001“ (~4 мин): одна цельная ведомость на 3–4 работника (не повтор шагов уровней), итог — вывод о нарушении и сумма недоплаты → „Акт проверки“». Правила расчёта те же: B × (k + s), B — большая из двух баз, недоплата = max(0, минимум − зарплата). Других правил не добавлять.

## Суть (~4 мин)
Игрок получает одну ведомость вымышленной организации за месяц: таблица из 4 работников (на 360×740 допустимо 3). Работает с ней как с одним документом, а не как с серией карточек:
1. Определяет базу B для организации один раз: МРОТ или региональный минимум (учебный регион, вымышленные цифры).
2. Для каждого работника отмечает «нарушение есть / нет» и, если есть, вводит сумму недоплаты. Коэффициент k у всех общий (регион), надбавка s может отличаться у работников — это исходные данные строки, а не новое правило.
3. Вводит итог: общую сумму недоплаты по организации и общий вывод («нарушения выявлены / не выявлены»).
4. Получает «Акт проверки».
В ведомости должны быть и работники с нарушением, и без него (минимум по одному каждого типа). Данные детерминированы по seed. Учебный режим: генерируется только по вымышленным регионам.

## Проверка и обратная связь
- Ответы проверяются по кнопке «Подписать акт», а не по каждой клетке отдельно. Неверные ячейки подсвечиваются; первая ошибка даёт короткую подсказку на уровне ячейки, повторная — разбор по этой строке (как на уровнях 3–4: «в ведомости / верно»). Ответы сами не раскрываются.
- Если неверно определена база B, все строки, зависящие от неё, не подсвечиваются ошибкой по отдельности. Подсказка говорит, что ошибка в базе.
- Ссылки на методичку — заглушки `TODO(Эрика)`; в интерфейсе их показывать нейтрально («Повторить: раздел о применимом минимуме»), без видимого текста TODO. Это же исправить на уровнях 3 и 4: в коде TODO остаётся, игрок его не видит.

## XP
- За финал: +100 с первой попытки подписания, +70 если исправился сам, +50 после подсказки или разбора (как на других уровнях).
- Бонус «все уровни» +150 из ТЗ Эрики: реализовать как начисление после прохождения всех **доступных** уровней (сейчас 3, 4 и финал). Когда появятся уровни 1–2, условие расширится; список уровней для бонуса держать в одном месте конфигурации.
- Финал открывается после прохождения уровней 3 и 4.

## «Акт проверки»
Документ в стиле темы «Зелёная лампа», как официальный бланк, но с явной пометкой «Учебный документ. Тренажёр по курсу...» (без гербов, без реальных органов и реальных организаций):
- номер акта, дата (текущая дата устройства), учебный регион, вымышленная организация;
- поле «Проверяющий»: имя, которое игрок вводит сам (по желанию, хранится только в localStorage, никуда не отправляется), и его звание из игры;
- таблица по работникам: начислено, применимый минимум, недоплата;
- итог: общая сумма недоплаты и вывод;
- сводка игры: набранный XP, звание, сколько дел с первой попытки;
- штамп «Проверка завершена».
Действия: «Сохранить как изображение» (PNG, 1600 px по ширине, рендер своими силами через SVG/canvas или маленькой зависимостью с MIT/Apache, указать лицензию) и «Распечатать» (print-CSS, A4, без фона сцены). На телефоне сохранение тоже должно работать (скачивание или share sheet, где он есть).

## Оформление
- Ведомость как широкий бланк «Форма 05 / Расчётная ведомость» на столе. На 1920×1080 таблица помещается без горизонтальной прокрутки; на 360×740 строки становятся карточками внутри одного документа.
- Поля ввода сумм принимают пробелы, запятую и «₽» (используй существующий парсер уровня 4).
- Анимации: подписание (росчерк или нажатие печати), появление акта как листа из-под ведомости; 150–400 мс, reduced-motion отключает.
- Размеры текста и контраст — как на прошлых этапах.
